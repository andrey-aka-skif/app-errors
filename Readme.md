# app-errors

> [!CAUTION]
> **Ветка `release/v2` архивная. Использовать её в новых проектах не следует.**
>
> Актуальная линия — 4.x в ветке `master`. Линия 2.x развития не получает:
> новая функциональность в неё не вносится, исправление ошибок и дальнейшая
> поддержка не гарантируются. Ветка сохраняется как эталон работы с
> поддерживаемой линией выпуска и точка восстановления для тех, кто ещё не
> перешёл на актуальную версию.
>
> **Версии обратно не совместимы.**

Npm-пакет, предоставляющий классы ошибок приложения, связанные с обращением к внешнему API и внутренней логикой.

## Установка

```shell
npm install @andrey-aka-skif/app-errors@lts-v2
```

`lts-v2` — dist-тег линии сопровождения. Он всегда указывает на последний
выпуск 2.x и не сдвигает `latest`, который принадлежит старшей версии пакета.
Годится и обычный диапазон:

```shell
npm install @andrey-aka-skif/app-errors@^2
```

## Быстрый старт

```js
import { SuperagentNetworkAppError as AppError } from '@andrey-aka-skif/app-errors'

try {
  const api = new SurveysApi()
  actualData.value = await api.surveysIdChannelsChannelIdGet(
    surveyId,
    channelId,
    OPTS
  )
} catch (responseError) {
  actualData.value = []
  error.value = new AppError(toValue(responseError))
}
```

Импорты по подпутям (`@andrey-aka-skif/app-errors/superagent`, `/axios`,
`/logic`, `/error-types`) продолжают работать: они ведут в тот же пакет и
отдают тот же набор классов.

## API

- `AppError` - базовый класс, от которого наследуются остальные. Задаёт поля `type` и `detail`.
- `LogicAppError` - класс, представляющий ошибки уровня логики приложения.
- `AxiosNetworkAppError` - класс, представляющий ошибки, полученные через библиотеку Axios.
- `SuperagentNetworkAppError` - класс, представляющий ошибки, полученные через библиотеку Superagent (а также через связку OpenApi Middleware + Superagent).
- `ErrorTypes` - перечисление типов ошибок, попадающих в поле `type`.

Оба сетевых класса представляются одинаково: `name` их экземпляров равен
`NetworkAppError`. Различать ошибки следует по полю `type`, а не по источнику.

Линия 2.x различает статусы 400, 401, 403, 404, 409 и 500. Остальные ответы —
в том числе 408, 422 и 429 — получают тип `Unknown` с сообщением «Неизвестная
ошибка»; тело ответа при этом сохраняется в `detail`. Набор распознаваемых
статусов в архивной ветке расширяться не будет, за ним следует идти в 4.x.
